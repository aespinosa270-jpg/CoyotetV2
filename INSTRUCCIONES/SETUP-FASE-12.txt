═══════════════════════════════════════════════════════════════════════════
FLUJO COMPLETO DE UNA ORDEN
═══════════════════════════════════════════════════════════════════════════

  1. Cliente: "Quiero 50kg de felpa polar a Pachuca"
  2. Bot: detecta intención + calcula envío + genera Stripe
  3. Bot llama generar_cobro_stripe con productos[] = [{titulo, cantidad, precio}]
  4. Tool handler:
       a) Genera Stripe session (lógica original)
       b) FASE 12: crea Order(status=PENDING, source=bot_v2) automáticamente
       c) Devuelve link al bot
  5. Bot envía link al cliente
  6. Cliente paga
  7. Stripe webhook → onStripePaymentSuccess → Order(status=PAID)
  8. Aparece en /crm/admin/bot/ordenes (tab "Pagadas")
  9. Logística click "📦 Preparar" → status=PROCESSING
  10. Logística click "🚚 Marcar enviada" → status=SHIPPED
  11. Logística click "✅ Marcar entregada" → status=DELIVERED


═══════════════════════════════════════════════════════════════════════════
FLUJO DE TELA NO MANEJADA
═══════════════════════════════════════════════════════════════════════════

  1. Cliente manda foto de popelina
  2. Vision V2 analiza → esManejada=false, telaIdentificada="popelina"
  3. Bot enriquece el system prompt con la info
  4. Bot responde algo como:
     "Identifiqué que es popelina (algodón liviano). Esa tela no la
     manejamos por ahora, pero registré su interés. ¿Cuántos metros
     necesitaría aproximadamente?"
  5. Bot llama registrar_tela_no_manejada con cantidad/uso
  6. Aparece en /crm/admin/bot/telas-solicitadas
  7. El equipo evalúa: "5 clientes pidieron popelina, vamos a agregarla"


═══════════════════════════════════════════════════════════════════════════
FLUJO DE PROGRAMACIÓN DE VOLUMEN
═══════════════════════════════════════════════════════════════════════════

  1. Cliente: "Para temporada escolar necesito 200kg de sportok mensual"
  2. Bot detecta señal "temporada escolar" + "mensual"
  3. Bot llama programar_volumen_temporada:
       tela_titulo: "Sportok"
       kg_por_periodo: 200
       periodo: "mensual"
       fecha_inicio: "2026-08-01"
       duracion_meses: 4
  4. Aparece en /crm/admin/bot/programaciones (estado: propuesta)
  5. Logística confirma disponibilidad y cambia a "confirmada"
  6. Cliente queda con compromiso de compra

KILL SWITCH — EMERGENCY STOP
═══════════════════════════════════════════════════════════════════════════

¿El bot está respondiendo cosas raras? ¿Hay un bug crítico?
APÁGALO en 10 segundos:

OPCIÓN 1 — Desde el dashboard:
  /crm/admin/bot/config → botón rojo "Apagar v2"

OPCIÓN 2 — Desde curl:
  curl -X POST `
    -H "Cookie: tu-cookie-admin" `
    -H "Content-Type: application/json" `
    -d '{"action":"kill"}' `
    https://TU_DOMINIO.com/api/admin/bot/kill-switch

OPCIÓN 3 — Directo en Redis:
  En Upstash console: SET v2:kill_switch 1

  Re-activar: DEL v2:kill_switch

SI ALGO SE ROMPE EN PRODUCCIÓN — CHECKLIST
═══════════════════════════════════════════════════════════════════════════

🔴 Si el bot da respuestas mal:
  → ACTIVAR KILL SWITCH inmediatamente
  → Investigar logs en Vercel
  → Revisar /crm/admin/bot/conversaciones para ver qué respondió mal
  → Si es problema de prompt: ajustar /crm/admin/bot/config (sin redeploy)
  → Si es problema de código: fix + deploy
  → Re-activar v2

🔴 Si Stripe webhook falla:
  → Las órdenes quedan en PENDING aunque el cliente pagó
  → Logística puede cambiar manualmente a PAID desde el dashboard
  → Investigar logs del webhook en Vercel

🔴 Si vision V2 está rechazando muchas telas conocidas:
  → Revisar el prompt en src/lib/bot/intelligence/vision/prompts.ts
  → La lista de "TELAS QUE COYOTE MANEJA" debe actualizarse
  → También editar /crm/admin/bot/catalogo si es ajuste de catálogo

🔴 Si las órdenes no se crean automáticamente:
  → Verificar que `prisma db push` corrió OK (campo `source` debe existir)
  → Revisar logs del tool executor
  → Manualmente: revisar /crm/admin/bot/conversaciones para ver si el
    bot llamó el tool correctamente
